# CineSense – Turing College AI Capstone Project

You are my senior software architect, AI engineer, full-stack developer, and technical mentor.

We are building **CineSense**, a distinctive AI-powered movie discovery application for my Turing College Capstone Project.

The project must be a genuinely functional, testable, explainable AI application — not just a beautiful frontend or a chatbot wrapper.

Communicate with me in German. Write code, technical documentation, identifiers, and architecture diagrams in English. Keep all user-facing application text in German initially.

## 1. Product Vision

**CineSense — Don't choose a movie. Choose a feeling.**

Traditional movie platforms focus on titles, genres, rankings, and browsing catalogs.

CineSense focuses on cinematic atmosphere, visual impressions, emotional preferences, and interactive discovery.

The central experience is a **Living Cinema Wall**.

Users arrive on a visually immersive homepage containing multiple animated cinematic worlds. Each world represents a mood or type of movie experience.

Examples:

- Mystery & Thriller — suspense, psychological tension, unexpected twists
- Beyond Reality — science fiction, space, futuristic worlds
- Feel Everything — romance, emotional drama
- Into the Unknown — adventure, exploration, epic journeys
- Dark & Strange — horror, supernatural mystery
- Laugh & Escape — comedy, uplifting entertainment

The homepage should feel like an interactive cinema installation, not an ordinary Netflix clone.

## 2. Core User Experience

### A. Living Cinema Wall

Build a responsive, cinematic homepage featuring a visually varied mosaic of six mood categories.

Each tile should support:

- Atmospheric imagery
- Optional short, muted, looping video previews when legally permitted
- Smooth hover and click interactions
- A clear category title and mood description
- Reduced-motion accessibility support
- Mobile-friendly behavior
- Graceful fallback to still images

Avoid autoplaying audio and avoid downloading or editing copyrighted movie scenes without permission.

Use original, licensed, or otherwise authorized visual assets.

### B. Enter a Movie World

When a user selects a mood category, open an immersive discovery experience.

Show:

- A mood description
- Related cinematic subcategories
- Relevant movie candidates
- Available official trailers or clips
- Film posters and metadata
- Simple feedback controls

Feedback examples:

- I like this atmosphere
- Too dark
- More suspense
- Less violence
- Something similar
- Not interested

### C. AI Movie Discovery Agent

The user can communicate naturally:

"I want something like Interstellar, but shorter and less complicated."

"I want a mystery with an unexpected ending, but no horror."

"Show me emotional science-fiction movies with strong acting."

The AI must interpret the request, use actual tools, retrieve real movie information, incorporate user feedback, and produce grounded recommendations.

Every recommendation must explain why the movie matches the user's preferences.

Never fabricate movie titles, cast members, ratings, availability, or trailers.

### D. Movie Details

Each movie detail view should contain, when available:

- Title and release year
- Synopsis
- Runtime
- Genres
- Director
- Main cast
- Ratings with source attribution
- Official trailer
- Related movies
- Reasons for recommendation
- Content preference warnings when reliable data exists

Actor profiles should show biography, filmography, and related movies.

## 3. AI Architecture

Use Python, LangChain, and LangGraph.

Design a stateful recommendation workflow with explicit graph nodes and conditional transitions.

Proposed workflow:

START
→ understand_intent
→ update_preferences
→ retrieve_candidates
→ enrich_movie_data
→ rank_candidates
→ generate_grounded_explanations
→ present_recommendations
→ receive_feedback
→ update_preferences / retrieve_candidates
→ END

Do not force every request through every node. Use conditional routing where appropriate.

Create real tools such as:

1. search_movies
2. discover_movies
3. get_movie_details
4. get_movie_credits
5. get_actor_details
6. get_movie_videos
7. get_movie_ratings
8. find_similar_movies
9. semantic_movie_search
10. filter_movies_by_preferences
11. record_user_feedback
12. explain_recommendation

Some of these may be deterministic application functions rather than LLM-callable tools. Clearly document which are which and why.

The LLM should select appropriate tools through structured function calling where agentic behavior is useful.

Implement:

- Typed tool parameters
- Clear tool descriptions
- Input validation
- Structured tool responses
- Error handling
- Tool-call tracing
- Session-level conversation memory
- Explicit LangGraph state
- Configurable model provider
- API cost and token controls

Avoid unnecessary multi-agent complexity.

## 4. Semantic Search and Embeddings

Implement meaningful semantic movie discovery.

Users should be able to search by concepts such as:

"Quiet, atmospheric science fiction about loneliness and identity."

Use embeddings to represent movie descriptions, themes, and available legally usable metadata.

Store vectors in a suitable local or database-backed vector store.

Clearly distinguish:

- Keyword search
- Metadata filtering
- Semantic vector search
- LLM reasoning

Do not claim that embeddings analyze video scenes unless an actual video-understanding pipeline has been implemented.

For the first version, cinematic mood may be represented using curated labels and movie metadata.

## 5. Data Sources and Copyright

Investigate TMDB as the primary movie metadata source.

Review the current API documentation, licensing, attribution, caching, and usage restrictions before implementation.

Consider:

- Movie metadata
- Posters
- Credits
- Actor profiles
- Ratings
- Trailer references

Use official, permitted video embeds where available.

Do not scrape streaming services, bypass DRM, or download copyrighted movie scenes.

If a requested feature cannot legally or technically be implemented, propose a compliant alternative.

Build a data provider abstraction so the application is not tightly coupled to a single API.

Provide a small fixture-based demo dataset so the application and tests work without external credentials.

## 8. Evaluation Strategy

Design a reproducible evaluation suite with at least 30 representative movie discovery scenarios.

Examples:

- Mood-based requests
- Similar-to-a-movie requests
- Runtime constraints
- Genre exclusions
- Requests with conflicting preferences
- Follow-up feedback
- Missing metadata
- Unavailable trailers
- Ambiguous movie titles
- Tool/API failures

Define measurable metrics such as:

- Constraint satisfaction
- Recommendation relevance
- Grounding accuracy
- Tool selection correctness
- Tool execution success
- Response latency
- Cost per recommendation

Include a deterministic baseline, such as genre and metadata filtering, for comparison with the AI-enhanced approach.

Separate automated tests from subjective recommendation evaluation.

## 9. Implementation Phases

Create an incremental development roadmap.

**Phase 1 — Foundation and Living Cinema Wall**

Build a visually impressive but functional homepage with six mood worlds, fixture movie data, responsive navigation, and a movie details view.

**Phase 2 — Real Movie Data**

Integrate the movie metadata provider, actor information, ratings, and official trailers.

**Phase 3 — AI Discovery Agent**

Implement LangGraph, tool calling, preference tracking, semantic search, and grounded recommendations.

**Phase 4 — Feedback and Personalization**

Add interactive feedback loops, session persistence, recommendation refinement, and transparent explanations.

**Phase 5 — Evaluation and Capstone Delivery**

Build evaluation datasets, metrics, documentation, architecture diagrams, demo scenarios, and presentation materials.

## 10. Engineering Rules

- Use test-driven development where practical.
- Keep business logic separate from UI components.
- Never hardcode API secrets.
- Do not fabricate API responses.
- Use mocks and fixtures for offline tests.
- Keep external API calls behind adapters.
- Add loading, empty, and error states.
- Make accessibility and responsive design part of the initial implementation.
- Record important architecture decisions.
- Do not overengineer.
- Do not build a generic movie search page as the primary experience.
- Do not sacrifice the actual AI functionality for visual polish.
